# 批次业务统计验收

更新日期：2026-10-08。

学校管理员在“批次统计”选择本校批次。`GET /api/portal/batch-statistics?batchId=` 返回指标与逐学生明细。跨学校批次返回 404，其他角色不能读取。

## 指标口径

| 指标 | 定义 |
| --- | --- |
| 学生基数 | 本批次学院当前已开通、启用账号的 STUDENT 学生档案；不是历史冻结名册 |
| 落实学生 | 学生在本批次有学校 APPROVED 且未终止、未被替代的安排；同一学生仅取最新有效安排 |
| 完成学生 | 以上安排已批准结项归档 |
| 落实率/完成率 | 对应学生人数 / 学生基数 × 100%，保留两位小数；无分母返回 null |
| 专业匹配率 | 明确匹配人数 / 专业要求已知的有效安排人数；按完整专业词项比较 |
| 专业未知 | 自主联系、岗位未填写专业或不限专业；不进入专业匹配率分母 |
| 材料缺失 | 有有效材料规则且至少一个必需类型的最新文件未审核通过的落实学生数 |
| 材料规则未配置 | 既无范围执行规则、也无启用材料检查的批次预警配置；不假设齐全 |

范围材料规则优先于批次预警要求。学生手动完成材料提醒不影响材料缺失统计。既有全局基础计数 API 保留；完整历史管理 API 多学校隔离仍属于 T19。

验证：前端语法和 12 项测试，MySQL verify 66 项全通过，无跳过并构建成功。回归核查两名学生分母、单人落实 50%、结项完成 50%、专业已知/未知、材料最新版通过和缺失、终止排除、跨校及学生拒绝；测试事务回滚。

真实浏览器批次 1094 显示学生基数 1、落实 1/100%、完成 0/0%、专业未知 1、专业匹配无分母、协议缺失 1。页面同时展示口径与逐学生明细。截图 `.local/batch-statistics-verified.png`。
