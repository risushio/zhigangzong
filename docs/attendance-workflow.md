# 考勤与请假闭环验收

完成日期：2026-10-07。T01 已完成，当前范围为单校本地试点。

## 使用流程与规则

在业务办理的“审批与过程跟踪”（管理员为“审批与导师分配”）列表，点击对应实习的“考勤与请假”。

1. 学校管理员按实习设置考勤要求并填写原因。默认关闭，不强制所有学生签到；设置变更保留历史。
2. 学校批准、企业确认到岗且有指导教师后，学生可在启用考勤的实习中办理签到、单日请假或补签。
3. 签到只能办理北京时间当天，直接形成通过记录；补签仅接受过去日期。所有日期必须在实习期间内。请假按一天申请，可申请实习期间的过去、当日或未来日期。
4. 请假与补签提交后为 `PENDING`。当前指导教师可批准、退回补充或拒绝；退回后学生补充原因并重提，日期与类型沿用原申请。
5. 同一实习同一天的待审、退回或通过记录互斥。已拒绝申请保留历史，允许新申请；重复签到或审批被拒绝。
6. 关闭要求后不能新增或重提，既有记录保持可读，教师仍能处理已提交申请。启用后可继续补充重提。

学生只访问本人实习；教师和企业导师按当前指导关系访问，企业导师还检查企业归属。企业导师只读，学校管理员负责配置、查看，审批仅由当前教师办理。改派后原教师失去访问及审批权限。招聘账号无考勤权限。

## 接口

所有接口在 `/api/portal` 下，写请求沿用登录 Session 与动态 CSRF 头。

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/placements/{id}/attendance` | 考勤要求、记录与要求历史 |
| PUT | `/placements/{id}/attendance-policy` | 管理员设置 `enabled` 与 `note` |
| POST | `/placements/{id}/attendance` | 学生提交 `attendanceDate`、`recordType`、`note` |
| GET | `/attendance/{id}` | 记录及原因/意见历史 |
| POST | `/attendance/{id}/resubmit` | 学生补充 `note` 并重新提交 |
| POST | `/attendance/{id}/review` | 教师填写 `decision` 与 `feedback` |

类型为 `CHECK_IN / LEAVE / MAKE_UP`，审批为 `APPROVED / RETURNED / REJECTED`。原因及意见必填，最多 480 字。新流程暂不办理历史骨架中的 `APPEAL`。

数据库复用 `attendance_record`，新增 `placement_attendance_policy`、`attendance_policy_event`、`attendance_record_event`。初始化以 `CREATE TABLE IF NOT EXISTS` 增量建表，不删除既有表和数据；未配置要求的实习默认关闭。事务先锁实习，再使用当前锁定读取检查要求、考勤状态及同日记录，串行处理同一实习的写操作。
