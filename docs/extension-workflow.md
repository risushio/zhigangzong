# 实习延期闭环验收

完成日期：2026-10-08。T02 已完成，当前面向单校本地试点。

## 办理流程

业务办理“审批与过程跟踪”（管理员为“审批与导师分配”）中的每条实习增加“实习延期”入口。

1. 学校已批准的实习，由学生申请新的结束日期并填写原因与安排；无需先确认到岗。
2. 新结束日期必须晚于当前实习结束日期，且不能早于北京时间今天。申请与退回不会修改实习日期。
3. 学校管理员批准、退回补充或拒绝。教师与企业导师按当前指导关系只读查看；企业导师同时检查企业归属。
4. 退回后学生可调整申请结束日期、补充原因并重提。原始实习日期及每次申请/审批内容、操作人、时间保留独立历史。
5. 批准与修改结束日期在同一事务中执行；周报及考勤自动使用新的实习期间。开始日期、岗位、单位、批次和导师关系保持原值。

学校审批决定单个实习的新结束日期，可超过原批次或岗位结束日期；不修改批次和岗位公共日期。统一日期规则归 T12，本轮不增加额外审批层级。

同一实习有待审或退回变更申请时不能再新增延期。通过或拒绝后可另行申请，新的申请以当时日期为原始快照。重复审批和已通过/拒绝申请的重提被拒绝。批准前核对当前实习日期与原快照，发生变化时禁止执行旧申请，管理员可拒绝待审申请后由学生重新申请。

学生只能操作本人实习，学校管理员只能处理本校申请；其他学生、学校或非当前指导教师不能读取。招聘角色不能访问延期流程，学生和导师不能代替学校审批。

## 真实接口

接口均位于 `/api/portal` 下；写请求使用当前登录 Session 和动态 CSRF 头。

| 方法 | 路径 | 请求或结果 |
| --- | --- | --- |
| GET | `/placements/{id}/extensions` | 当前实习与延期申请列表 |
| POST | `/placements/{id}/extensions` | 学生填写 `endDate`、`reason` |
| GET | `/extensions/{id}` | 申请及独立历史 |
| POST | `/extensions/{id}/resubmit` | 学生补充 `endDate`、`reason` |
| POST | `/extensions/{id}/review` | 学校填写 `decision`、`comment` |

决定为 `APPROVED / RETURNED / REJECTED`，原因和审批意见必填、最多 480 字。原/申请日期快照为包含 `startDate` 与 `endDate` 的 JSON。

复用 `change_request` 的 `EXTEND` 类型；新增 `change_request_event` 存储历史。增量建表保留现有数据。写事务先锁实习，再锁申请、读取当前有效变更记录，防止并发重复申请和审批覆盖。
