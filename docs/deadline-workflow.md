# 截止提醒与通知待办验收

更新日期：2026-10-08。

范围执行规则优先，无范围规则时采用既有批次预警的材料/周报配置。无配置不生成截止提醒。材料检查必需类型最新文件是否审核通过；周报检查是否已有已提交或已批阅报告覆盖要求周期，草稿与退回不算完成。

截止日前 3 天起（包含逾期）生成本人通知，显示实习编号、具体材料/周期和截止日期。材料截止为实习开始日加配置天数；周报截止为周期末日加宽限天数。通知 `due_at` 为截止日北京时间 23:59:59。新增 `deadline_reminder` 保存稳定去重键；同一实习/条件/截止日期只通知一次。材料通过或周报提交后，下一次检测自动写 `completed_at`；终止、替代和归档安排也完成其旧提醒。修改规则导致截止日变化时旧提醒完成，新截止日采用新键。

本地服务启动 60 秒后执行一次，随后每小时检测；`app.reminders.enabled=false` 可关闭后台检测，学校仍可在“批次业务规则”执行全校已配置规则的检测。测试环境固定关闭后台任务，数据库回归事务回滚，不由后台任务写入演示记录。

`POST /api/portal/reminders/scan` 仅本校学校管理员，返回新增数量；`POST /api/portal/notifications/{id}/read` 与 `/complete` 仅通知本人，分别保存已读/完成时间。手动完成待办仅表示通知待办已办，不修改材料审核、周报或学校批准状态。

前端语法及 12 项测试、MySQL verify 66 项无失败无跳过并构建通过。回归覆盖材料和报告提醒、重复检测 0 新增、最新材料通过自动完成、已读不完成、手动完成不伪造周报、跨学生访问及角色边界。

真实浏览器：实习 859 出现协议及 2026-09-24 至 09-30、10-01 至 10-07 两期周报提醒；协议通知先标记已读后仍可完成待办，再完成后显示“已读 已完成待办”。截图 `.local/reminders-verified.png`。最终持久化复核见第三优先级总览。
