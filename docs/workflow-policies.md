# 范围业务规则验收

更新日期：2026-10-08。

学校管理员“范围执行规则”保存完整配置，优先级为批次＋专业、批次、学院＋专业、学院。专业按当前学生档案匹配，学院采用批次所属学院；不合并多层字段。未配置时保留既有办理行为。新增表 `scoped_workflow_policy`、`scoped_workflow_policy_event`，不改写原表，查询兼容本机新旧表的 UTF-8 排序规则。

`GET/POST /api/portal/workflow-policies` 查询本校规则、学院及最近 100 条配置历史/保存规则；`GET /api/portal/placements/{id}/workflow-policy` 按本人、本校或当前指导关系返回当前生效规则及版本。

- 学校初始实习审批仍由学校管理员办理；批准时校验最少实习天数，启用审批材料门槛时校验各类型最新已审核文件。退回/拒绝不受批准门槛限制。
- 周报开启周期约束后，保存/提交均要求从实习开始日按配置天数分期，最后一期截止实习结束日。
- 默认签到采用范围规则；显式单实习启用/关闭配置优先，无任何配置保持关闭。
- 必需材料用于结项门槛，并供截止提醒与材料缺失统计使用；截止日为实习开始日加材料天数。
- 独立批次评分优先；未配置独立评分时使用范围权重及及格线。评分快照包含范围规则 ID 和版本，变更后须重新复核；已归档使用冻结快照。
- 结项检查范围规则要求的必需材料及完整已批阅周报周期，并冻结范围规则版本；规则变化导致旧申请需退回重提。

验证：前端语法和 12 项测试，MySQL verify 63 项无失败、无跳过及构建通过。回归覆盖学院/专业/批次优先级、审批天数和材料阻止、7 天周报、签到单实习覆盖、继承评分 91 分及独立批次评分覆盖为 80 分、规则版本递增、跨学校和角色拒绝，事务回滚。
