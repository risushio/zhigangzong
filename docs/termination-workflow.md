# 实习终止与重新安排验收

更新日期：2026-10-08。T04 采用终止后原记录仅查询方案。

## 业务规则

- 学生对学校已批准、未被替代且尚未终止的实习申请终止，说明终止原因与交接安排；学校管理员批准、退回补充或拒绝。无需先办理到岗，终止在学校批准时立即生效。
- 申请前及退回期间实习仍按原规则办理。终止、延期与换岗/换单位申请互斥；有待审或退回变更时不能新建另一变更。
- 学生补充重提保留原安排和每次原因、意见、操作人、时间。批准或重提时核查原单位、岗位、学校决定、日期、导师关系，原安排已变化则不执行旧申请。学校可拒绝关闭退回申请，避免过时申请无法重提又阻塞后续业务。
- 批准终止以独立记录保存申请编号和实际批准时间，不覆盖原学校审批、日期、单位、岗位、导师、到岗和过程资料。批准、状态保存和历史事件在同一事务内执行，重复审批不会产生重复终止记录。
- 终止后原记录仅供授权历史查询，禁止导师分配/改派、到岗、周报新建/编辑/提交/批阅、考勤配置/申请/重提/审批、材料上传/审核、延期及再次终止。已提交但尚未处理的周报、考勤、文件保持原状态，不自动改成通过或拒绝。
- 本人、本校管理员及原记录的指导教师、企业导师继续按原授权读取历史；企业导师同时受企业归属限制。原文件仍可预览、下载并核验字节；个人简历库及其他有效实习不受影响。
- 继续实习须通过 T03 的“换岗与换单位”办理：学校审批后创建关联新记录，原终止状态和历史继续保留。终止后的自主目标可填同单位同岗位，普通申报仍不能直接绕过关联审批重复创建同一批次记录。
- 新记录不继承终止标记，重新分配双导师、确认到岗、办理材料与适用考勤要求；原周报、考勤、文件不会迁移到新记录。

## 页面与接口

各角色“审批与过程跟踪”新增“实习终止”，列表展示“已终止”标记。终止详情展示每次处理历史，过程、考勤、延期和文件页面显示只读说明并隐藏写入操作。关联新安排入口仍可使用。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET / POST | `/api/portal/placements/{id}/terminations` | 授权查询 / 学生申请 |
| GET | `/api/portal/terminations/{id}` | 申请详情与处理快照 |
| POST | `/api/portal/terminations/{id}/resubmit` | 学生补充原因并重提 |
| POST | `/api/portal/terminations/{id}/review` | 学校批准、退回或拒绝 |

申请与重提体为 `reason`，审批体为 `decision`、`comment`，原因和意见均必填、最多 480 字。写请求要求 Session 与 CSRF。退回申请只能重提，或由学校 REJECTED 关闭，不能直接批准。

复用 `change_request` 的 TERMINATE 类型及 `change_request_event`，新增 `placement_termination`，按实习唯一保存终止申请及时间。追加建表初始化，保留已有数据。实习查询返回 `terminationRequestId`、`terminatedAt`；写入检查通过同一锁定查询读取实习、终止和替代关系。
