# 换岗、换单位与拒绝后重新安排验收

更新日期：2026-10-08。T03 采用关联新实习记录方案。

## 业务规则

- 学生在已批准或已拒绝的实习中申请换岗、换单位；沿用原学生和批次。平台目标必须是本人已确认录用、尚未用于任何实习安排的申请；自主目标须填写单位代码、名称、联系人、地址、岗位、工作内容和日期。
- 新日期有序且在原批次范围内，平台目标同时受岗位期间限制。原岗位不变的安排不接受；本功能不用于单纯延期。暂停、拒绝的企业不能作为目标，平台单位和岗位须已审核通过；自主单位沿用现有学校核验规则。
- 同一实习的延期与换岗/换单位申请互斥，待审或退回时不能再申请。学校可批准、退回补充或拒绝；退回后学生可调整目标安排重提，拒绝后可重新申请。
- 批准在一个事务内新建实习、记录学校批准、关联原记录与新记录、保存变更事件。申请时的原单位、岗位、日期、学校审批状态和导师关系保留快照；批准和重提时核对原安排，批准时重新核对目标状态和资料，防止执行过时申请或重复审批。
- 原记录的单位、岗位、学校决定、日期、导师、到岗、周报、考勤和文件均不覆盖。关联成立后，原记录只供授权历史查询，禁止导师改派、到岗、周报写入/批阅、考勤配置/申请/审批、材料上传/审核及继续延期或换岗。
- 新记录已由学校批准，双导师均待分配、到岗待确认、考勤默认关闭，周报和材料为空；需重新办理指导关系、到岗、材料及适用考勤要求。分配同一位校内教师也必须重新执行分配。
- 学生与本校管理员可沿关联查看新旧安排；教师按各记录的指导关系访问，企业导师同时受所属企业限制。原导师保留原安排历史访问权，不会自动获得新安排的权限，新导师也不会自动获得原材料。
- 原拒绝记录保持 REJECTED 和原审批意见，新安排另存 APPROVED 与本次批准记录。普通自主申报/平台学校审批仍禁止绕过关联流程直接重复创建同一批次实习。

## 页面与接口

各角色“审批与过程跟踪”列表新增“换岗与换单位”，标明原记录或替代后的历史记录；学生选择已录用目标或填报自主目标，学校在申请详情中处理，详情展示每次独立快照。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET / POST | `/api/portal/placements/{id}/transfers` | 授权查询 / 学生申请 |
| GET | `/api/portal/transfers/{id}` | 申请与历次历史 |
| POST | `/api/portal/transfers/{id}/resubmit` | 学生补充重提 |
| POST | `/api/portal/transfers/{id}/review` | 学校批准、退回或拒绝 |

申请体为 `source`、`startDate`、`endDate`、`reason`，平台目标带 `applicationId`，自主目标带 `self`（字段同现有自主申报，批次和日期与原批次、新安排一致）。审批体为 `decision`、`comment`。写请求要求 Session 与 CSRF。

复用 `change_request`（CHANGE_JOB / CHANGE_ENTERPRISE）及 `change_request_event`。新增 `placement_replacement`，原实习、新实习和申请分别唯一关联；使用追加建表初始化，保留已有数据。实习接口返回 `previousPlacementId` / `replacementPlacementId`，录用列表返回 `placementAssigned`，供页面排除已使用录用。

## 后续边界

终止申请与终止后的只读规则已完成，见 [终止验收](termination-workflow.md)；终止后可通过本流程创建关联新安排，保留原终止记录。关联替代保留历史审批状态，统计指标在 T14 需按 `placement_replacement` 排除被替代记录，避免把同一批次历史安排作为当前落实数。全量历史管理 API 的多学校隔离仍属于 T19，当前保持单校试点描述。
